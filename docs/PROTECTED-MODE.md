# Защищённый режим — локальная тестовая версия 1.6.0-dev

Публичного релиза и push в этой работе нет. Последняя исходная версия сохранена
локальным коммитом 3cd295e и меткой baseline/android-v1.5.0. Сведения об исходной
APK и откате — в BASELINE-1.5.0.md. Версия разработки: versionCode 30, прежний
applicationId и исходный ключ подписи. Настройка protectedMode отсутствует в старых
настройках и загружается как false. Прежний пользовательский выбор connectionGuard
сохраняется, но в защищённом режиме контроль соединения обязателен.

## Поведение

- Галочка выключена: прежние службы AmneziaWG/Xray и прежние правила работы.
- Галочка включена: все профили обслуживает ProtectedVpnService в отдельном
  процессе :protected. Служба хранит собственный дескриптор TUN; native-движкам
  передаются дополнительные дескрипторы. Закрытие движка не должно закрывать
  последний дескриптор Android VPN.
- AmneziaWG исполняется в дополнительном процессе :protectedAwg через закрытый
  AIDL-сервис. Владелец TUN передаёт ему только дубликат fd. Его Go runtime нельзя
  загружать в процесс libXray: живой тест обнаружил SIGSEGV при таком сочетании.
  Остановка или падение AWG-процесса не закрывает мастер-дескриптор владельца.
- Неисправный сервер, отменённый запуск или пауза между попытками: транспорт
  останавливается, TUN остаётся назначенным приложениям. Отсутствие читающего
  движка не даёт их пакетам выйти через этот TUN; обычная сеть им не разрешается.
- При смене конфигурации TUN новая связь создаётся той же VPN-службой до закрытия
  предыдущего владельческого дескриптора. Разрешённого прямого промежуточного
  профиля нет. Устойчивость этого перехода требует проверки на POCO/HyperOS.
- После отказа всех профилей сохраняется блокировка и прежний интервал повторной
  попытки 15 секунд. Статус BLOCKED публикует сама VPN-служба только после
  успешного создания интерфейса, а не по одному факту включённой галочки.
- Ручное OFF вне дома: остановить движок, сохранить блокировку. Для прямого
  интернета необходимо снять галочку. При включённом таймере возврата OFF может
  позднее вернуться в Авто как прежде.
- Домашняя сеть в Авто: снять TUN и разрешить обычное подключение. Ручное ON
  защищает и дома. Неопределённая/неизвестная сеть считается внешней.
- Нет профилей: защищённый режим вне дома держит блокировку и предлагает добавить
  профиль. Списки приложений не сбрасываются. При отключении галочки сохраняются
  исходные настройки обычного режима.

## DNS, IPv6 и загрузка транспорта

Для защищаемых UID устанавливаются полный маршрут IPv4 и DNS 1.1.1.1. IPv6
не объявляется и не разрешается через allowFamily/allowBypass: он блокируется
Android для этих UID. Импортированные узкие маршруты AWG не должны создавать
обход: Android направляет IPv4 в TUN, а неподдерживаемое peer-направление может
только перестать работать. В защищённом режиме DNS из исходного AWG-профиля
заменён на публичный DNS внутри туннеля; частные DNS-имена такого профиля могут
не работать. Исходная конфигурация профиля не редактируется.

В Xray обычные DNS-запросы перехватываются, запросы AAAA получают пустой ответ,
а встроенный DoH https://1.1.1.1/dns-query направляется в тот же proxy outbound.
Прямого freedom-outbound нет. Собственные DoH/DoT выбранного приложения также
попадают в его VPN-маршрут; блокировку системного Private DNS необходимо проверить
на конкретном Android, а не выводить из JSON-конфигурации.

Адреса серверов AWG/VLESS/Hysteria и peer qWDTT сохраняются отдельно от
конфигурации профилей. Известный IP используется сразу, без ожидания DNS,
включая случай истечения TTL. Это подсказка для подключения: исходные SNI,
проверка сертификатов и ключи протокола сохраняются. Работающее соединение
при обновлении адреса не перезапускается; новый IP применяется при следующей попытке.

Первое разрешение и обновление домена самого VPN-сервера используют DNS
физической сети в обоих режимах. Это служебное разрешение адреса до готовности
туннеля: оператор может видеть эти имена. Оно не используется для DNS выбранных
приложений. Если DNS недоступен, уже известный IP остаётся пригодным для попытки;
новый домен без сохранённого IP требует доступного DNS. Литеральные IP его
не требуют. Дополнительные публичные DNS-провайдеры не добавлены.

Фоновая проверка запускается через 30 секунд и затем раз в 15 минут, только
для разрешённых профилей с уже известными адресами; свежие записи пропускаются.
TTL ограничен сверху одним часом. После отказа соединения дополнительно
запрашивается обновление адреса, не блокирующее команды туннелю. Ошибка DNS
оставляет предыдущий IP. Отмена режима/отключение профиля отменяет обновление.
Системное планирование Android может задерживать периодическую работу во сне.

Хранилища адресов режимов остаются отдельными; записи обычного режима не
заменяют записи защищённого. Обычный режим может использовать уже известную
защищённую запись. Оба хранилища зашифрованы AES-GCM тем же Keystore-ключом,
с отдельными файлами и контекстом шифрования, до 64 доменов каждое.

qWDTT использует DNS текущей физической сети для собственных служебных имён
VK/ОК и TURN. Android передаёт адреса DNS в закрытом файле приложения и обновляет
его при изменениях сети; native-клиент перечитывает файл при каждом DNS-запросе.
Нового локального DNS-сервера нет. При пустом/невалидном файле нет перехода на
произвольный публичный DNS. Этот Go-резолвер не применяется к SOCKS-трафику
приложений: его DNS использует внутреннюю сеть netstack и туннель.
Native-процесс, как и раньше, требует исключения UID AutoTurn
из TUN. Это исключение не распространяется на пользовательские выбранные
приложения. Проверка qWDTT выполняется через авторизованный SOCKS-вход того же
Xray, а не напрямую. Капча направляется в службу активного режима.
Служебный bootstrap не скрывает от DNS-провайдера исходный адрес или имена
служебных серверов; это не запросы выбранных приложений. Их DNS остаётся в VPN.

## Границы защиты

Это защита после успешного установления локального VPN при работающей службе.
При уничтожении процесса :protected, Android force-stop, отзыве разрешения,
перехвате VPN другим приложением, перезагрузке до старта службы или ошибке
establish приложение само не может гарантировать блокировку. Приложение показывает
ошибку, а не объявляет несуществующую защиту активной. Системный lockdown не
включается: он требует отдельного проектирования совместимости с исключениями,
qWDTT и выключением дома. Не представлять этот режим как системный firewall.

Назначение режима — удерживать трафик на выбранном VPN-маршруте; географию
VPN-выхода он не определяет. Профиль lench с российским выходом не станет
зарубежным от включения галочки. Серверные обходы/перенаправление и география
выхода проверяются отдельно.

## Выполненные локальные проверки

- tools/test-protected.ps1: 97 проверок правил режима и DNS wire-кодека, включая
  ручное OFF, домашнюю сеть, пустой список профилей, чужой transaction ID,
  NXDOMAIN/SERVFAIL, IPv6-only, некорректные имена и все усечения DNS-ответа.
- tools/test-qwdtt.ps1: 28 проверок парсера, 7 SOCKS-тестов и живая локальная
  цепочка Xray → авторизованный SOCKS с TCP/UDP.
- Gradle assembleDebug, assembleDebugAndroidTest и lintDebug проходят.
- Подпись собранной APK совпадает с исходной APK 1.5.0. SHA256 сертификата:
  6b8278762210878769ec313ec22a0cc590dcdd06f47c7ddb2264f63b76c15de2.

На POCO F7 / Android 16 выполнены 26 тестов ModelValidationTest.
ModelValidationTest проверяет значение false по умолчанию, слияние сохранений
со старым экраном настроек и сохранение обоих списков приложений.

Живой тест с двумя заведомо недоступными профилями AWG/Hysteria прошёл для ONLY
и EXCLUDE: ручное OFF, переходы между движками и пауза после отказа всех профилей.
Сохранялся VPN, отдельное приложение не получало UDP DNS и HTTPS. Первоначальная
сборка тест не прошла из-за SIGSEGV двух Go runtime; разделение процессов устранило
этот воспроизводимый сбой. Сохранённые настройки после теста восстановлены побайтно.

Живые Hysteria, lench и «Каскад мой» передали DNS, HTTPS и 256 КиБ TLS-данных через
VPN; ручное OFF после каждого подключения блокировало DNS и HTTPS. Имена endpoint
Hysteria разрешены через защищённый TLS bootstrap. Для Android Socket сначала
привязывается к локальному порту: ленивый Socket() ещё не имеет fd для protect().
В QwdttState проверка живого владельца принимает :xray и :protected; иначе работающий
qWDTT ошибочно считался неактивным в новом режиме.

qWDTT после исправления прошёл тот же живой тест: DNS, HTTPS, внешний IP
45.67.202.147, 256 КиБ TLS-данных и блокировка после ручного OFF.

Непрерывный независимый watcher проверен положительным контролем без VPN
(7 успешных внешних TLS-сеансов и свежий DNS-ответ). При отказах AWG/Hysteria
для ONLY и EXCLUDE — по 88 попыток за 45 секунд, ни одного внешнего TLS-сеанса
или содержательного DNS-ответа. При переходах удерживаемого AWG↔qWDTT и смене
списков — 89 попыток без выхода. TCP connect сам по себе недостаточен: gVisor
может завершать локальный TCP handshake до успешного outbound. Локальные DNS
SERVFAIL/REFUSED также не считаются ответами внешнего резолвера. Это проверка
наблюдаемого поведения, а не замена внешнего захвата исходящих пакетов.

В заблокированном состоянии проверен Wi-Fi→мобильная сеть→Wi-Fi: на каждом
этапе отдельное приложение оставалось в VPN, не получало DNS и HTTPS.
Chrome проверен через Hysteria на мобильной сети, без домашнего роутера:
BrowserLeaks показал IP 138.16.143.97 и 16 DNS-серверов Cloudflare в Нидерландах,
1 ISP / 1 location. Российских DNS в этом результате нет.
Изначальные Private DNS (opportunistic) и системный lockdown не менялись.
Доступной внешней IPv6-связности положительный контроль не обнаружил:
испытания на полноценной IPv6-сети остаются отдельной проверкой.

Результаты сохранены локально в artifacts/protected-device-*.txt и снимке
artifacts/protected-browser-dns-mobile.png. Секреты и зашифрованные резервные
копии находятся в игнорируемом .work/protected-device-20261108, не в Git.

## Повторный аудит и оставшиеся проверки

Дополнительный аудит на роутере без защиты и исправления жизненного цикла служб
описаны в [ANDROID-ROUTER-AUDIT-2026-11-08.md](ANDROID-ROUTER-AUDIT-2026-11-08.md).

Живой аудит запускается только явными opt-in флагами и временно изменяет маршруты.
Перед повторным тестом создать резервную копию. Установка обновлением, без удаления приложения и без очистки
Android Keystore. Сначала сверить данные профилей и выключенное значение галочки.

1. Галочка выключена: проверить привычные соединения, оба списка, плитку, Авто,
   домашнюю сеть и настройки после обновления.
2. Галочка включена: проверить каждый имеющийся AWG/Hysteria/VLESS/qWDTT профиль,
   внешний IP, свежие DNS, собственный DNS браузера и Private DNS Android.
3. Разорвать связь с сервером, не убивая владельца TUN. Проверить поток проб
   отдельного выбранного приложения, смену профилей и паузу отказа всех профилей.
4. Ручное OFF должно сохранить BLOCKED вне дома; OFF→ON возобновляет попытки;
   выключение галочки возвращает прежнюю маршрутизацию. Проверить оба списка
   приложений и прямую работу исключений.
5. Wi-Fi↔мобильная сеть, уход из домашней сети/возврат, выключенный экран/Doze,
   qWDTT-капча, частые команды и сохранение настроек после перезапуска UI.
6. Отдельно продемонстрировать границу force-stop/отзыва разрешения. Не записывать
   этот сценарий как успешно защищённый. Для вывода «нет DNS-утечек» дополнить
   браузерные проверки наблюдением пакетов на контролируемой сети/сервере.

Подготовлен opt-in ProtectedModeDeviceTest с двумя нерабочими loopback-профилями
AWG и Hysteria: проверяет ручное OFF, оба списка, смену движков и отказ всех
профилей, отдельно HTTPS и свежий UDP DNS. Он временно заменяет настройки,
восстанавливает settings.enc в tearDown. Отдельный тест переключает Wi-Fi на
мобильную сеть и обратно; первоначальное включённое состояние Wi-Fi восстанавливается
в tearDown. Системный lockdown и настройка Private DNS не меняются.
Во время теста маршрутизация телефона временно меняется; использовать только
после согласования, не во время работы с чувствительными приложениями.

После установки тестовой APK явная команда запуска:

```powershell
.\.sdk\platform-tools\adb.exe shell am instrument -w -e class app.autoturn.vpn.ProtectedModeDeviceTest -e protectedModeAudit true app.autoturn.vpn.test/android.test.InstrumentationTestRunner
```

Без protectedModeAudit=true проверки отказов/смены сети пропускаются. Реальные
профили требуют protectedRealProfiles=true, Chrome — protectedBrowserAudit=true.
Ни один из этих тестов не заменяет внешнего захвата DNS. Публичный релиз возможен только
после проверки на телефоне и отдельного решения пользователя.
