# Защищённый режим — локальная тестовая версия 1.6.0-dev

Публичного релиза и push в этой работе нет. Последняя исходная версия сохранена
локальным коммитом 3cd295e и меткой baseline/android-v1.5.0. Сведения об исходной
APK и откате — в BASELINE-1.5.0.md. Версия разработки: versionCode 30, прежний
applicationId и исходный ключ подписи. Настройка protectedMode отсутствует в старых
настройках и загружается как false. Прежний пользовательский выбор connectionGuard
сохраняется, но в защищённом режиме контроль соединения обязателен.

## Поведение

- Галочка выключена: прежние службы AmneziaWG/Xray и прежние правила работы.
- Галочка включена: все профили обслуживает ProtectedVpnService в отдельном
  процессе :protected. Служба хранит собственный дескриптор TUN; native-движкам
  передаются дополнительные дескрипторы. Закрытие движка не должно закрывать
  последний дескриптор Android VPN.
- Неисправный сервер, отменённый запуск или пауза между попытками: транспорт
  останавливается, TUN остаётся назначенным приложениям. Отсутствие читающего
  движка не даёт их пакетам выйти через этот TUN; обычная сеть им не разрешается.
- При смене конфигурации TUN новая связь создаётся той же VPN-службой до закрытия
  предыдущего владельческого дескриптора. Разрешённого прямого промежуточного
  профиля нет. Устойчивость этого перехода требует проверки на POCO/HyperOS.
- После отказа всех профилей сохраняется блокировка и прежний интервал повторной
  попытки 15 секунд. Статус BLOCKED публикует сама VPN-служба только после
  успешного создания интерфейса, а не по одному факту включённой галочки.
- Ручное OFF вне дома: остановить движок, сохранить блокировку. Для прямого
  интернета необходимо снять галочку. При включённом таймере возврата OFF может
  позднее вернуться в Авто как прежде.
- Домашняя сеть в Авто: снять TUN и разрешить обычное подключение. Ручное ON
  защищает и дома. Неопределённая/неизвестная сеть считается внешней.
- Нет профилей: защищённый режим вне дома держит блокировку и предлагает добавить
  профиль. Списки приложений не сбрасываются. При отключении галочки сохраняются
  исходные настройки обычного режима.

## DNS, IPv6 и загрузка транспорта

Для защищаемых UID устанавливаются полный маршрут IPv4 и DNS 1.1.1.1. IPv6
не объявляется и не разрешается через allowFamily/allowBypass: он блокируется
Android для этих UID. Импортированные узкие маршруты AWG не должны создавать
обход: Android направляет IPv4 в TUN, а неподдерживаемое peer-направление может
только перестать работать. В защищённом режиме DNS из исходного AWG-профиля
заменён на публичный DNS внутри туннеля; частные DNS-имена такого профиля могут
не работать. Исходная конфигурация профиля не редактируется.

В Xray обычные DNS-запросы перехватываются, запросы AAAA получают пустой ответ,
а встроенный DoH https://1.1.1.1/dns-query направляется в тот же proxy outbound.
Прямого freedom-outbound нет. Собственные DoH/DoT выбранного приложения также
попадают в его VPN-маршрут; блокировку системного Private DNS необходимо проверить
на конкретном Android, а не выводить из JSON-конфигурации.

Начальный адрес VPN-сервера требуется узнать до подключения. Только имена
серверов AWG/VLESS/Hysteria разрешаются отдельным TLS-запросом на 1.1.1.1:853
с проверкой сертификата one.one.one.one и идентификатора DNS-транзакции.
Нет перехода на системный/UDP DNS при ошибке: профиль считается недоступным.
Литеральные IPv4 не требуют этой проверки. Если DoT блокируется сетью, профили
с доменным endpoint могут не подключиться; это отдельный предмет испытаний.

qWDTT использует фиксированный DoH https://1.1.1.1/dns-query для собственных
служебных имён. Его native-процесс, как и раньше, требует исключения UID AutoTurn
из TUN. Это исключение не распространяется на пользовательские выбранные
приложения. Проверка qWDTT выполняется через авторизованный SOCKS-вход того же
Xray, а не напрямую. Капча направляется в службу активного режима.
Служебный bootstrap не скрывает от DNS-провайдера исходный адрес подключения к
нему; это не запросы выбранных приложений. Их DNS не должен использовать этот путь.

## Границы защиты

Это защита после успешного установления локального VPN при работающей службе.
При уничтожении процесса :protected, Android force-stop, отзыве разрешения,
перехвате VPN другим приложением, перезагрузке до старта службы или ошибке
establish приложение само не может гарантировать блокировку. Приложение показывает
ошибку, а не объявляет несуществующую защиту активной. Системный lockdown не
включается: он требует отдельного проектирования совместимости с исключениями,
qWDTT и выключением дома. Не представлять этот режим как системный firewall.

Назначение режима — удерживать трафик на выбранном VPN-маршруте; географию
VPN-выхода он не определяет. Профиль lench с российским выходом не станет
зарубежным от включения галочки. Серверные обходы/перенаправление и география
выхода проверяются отдельно.

## Проверка на телефоне — отдельный следующий этап

Не устанавливать/запускать device-аудит автоматически только потому, что телефон
виден через ADB. Перед тестом согласовать временное изменение маршрутов и создать
резервную копию. Установка обновлением, без удаления приложения и без очистки
Android Keystore. Сначала сверить данные профилей и выключенное значение галочки.

1. Галочка выключена: проверить привычные соединения, оба списка, плитку, Авто,
   домашнюю сеть и настройки после обновления.
2. Галочка включена: проверить каждый имеющийся AWG/Hysteria/VLESS/qWDTT профиль,
   внешний IP, свежие DNS, собственный DNS браузера и Private DNS Android.
3. Разорвать связь с сервером, не убивая владельца TUN. Проверить поток проб
   отдельного выбранного приложения, смену профилей и паузу отказа всех профилей.
4. Ручное OFF должно сохранить BLOCKED вне дома; OFF→ON возобновляет попытки;
   выключение галочки возвращает прежнюю маршрутизацию. Проверить оба списка
   приложений и прямую работу исключений.
5. Wi-Fi↔мобильная сеть, уход из домашней сети/возврат, выключенный экран/Doze,
   qWDTT-капча, частые команды и сохранение настроек после перезапуска UI.
6. Отдельно продемонстрировать границу force-stop/отзыва разрешения. Не записывать
   этот сценарий как успешно защищённый. Для вывода «нет DNS-утечек» дополнить
   браузерные проверки наблюдением пакетов на контролируемой сети/сервере.

Подготовлен opt-in ProtectedModeDeviceTest с двумя нерабочими loopback-профилями
AWG и Hysteria: проверяет ручное OFF, оба списка, смену движков и отказ всех
профилей, отдельно HTTPS и свежий UDP DNS. Он временно заменяет настройки,
восстанавливает settings.enc в tearDown и не трогает Wi-Fi/системный lockdown.
Во время теста маршрутизация телефона временно меняется; использовать только
после согласования, не во время работы с чувствительными приложениями.

После установки тестовой APK явная команда запуска:

```powershell
.\.sdk\platform-tools\adb.exe shell am instrument -w -e class app.autoturn.vpn.ProtectedModeDeviceTest -e protectedModeAudit true app.autoturn.vpn.test/android.test.InstrumentationTestRunner
```

Без protectedModeAudit=true этот живой тест пропускается. Он не заменяет проверки
реальных профилей, qWDTT и внешнего захвата DNS. Публичный релиз возможен только
после проверки на телефоне и отдельного решения пользователя.
