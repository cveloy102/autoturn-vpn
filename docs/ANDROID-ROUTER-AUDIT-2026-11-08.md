# Дополнительный Android-аудит, 8 ноября 2026

POCO F7, Android 16, локальная 1.6.0-dev (versionCode 30). Публичного релиза и
push нет. Пользователь разрешил проверку на роутере без защиты и переходы между
ним и сохранённой сетью Keen_5G. Исходные зашифрованные настройки сохранены в
игнорируемом .work/protected-device-plain-router/settings.enc. Приватные настройки
и снимки с реальным домашним IP в Git не включаются.

## DNS в Chrome на роутере без защиты

BrowserLeaks открывался с ручным ON и включённым защищённым режимом. Тест проверял
подключение к нужному SSID перед запуском и каждые 500 мс во время 35-секундного
наблюдения, исключая незаметный переход к Keen_5G. Итоги проверены по снимкам экрана.

| --- | --- | --- |
| hysteria | 138.16.143.97, Нидерланды | Только Cloudflare, Нидерланды |
| lench | 153.80.246.202, российский VPS | Только Cloudflare, Финляндия |

Реальный IP домашнего подключения и DNS домашнего провайдера в этих результатах
VPN не обнаружены. Без VPN сравнительный тест показывал российское подключение
провайдера и смешанный набор резолверов. Количество адресов Cloudflare меняется
между запусками; само по себе несколько адресов не означает утечку.

Российский выход проверочного сайта у lench остаётся свойством серверной
маршрутизации каскада. Это не домашний IP. Настройки сервера не менялись;
маршрут именно Claude отдельно этим браузерным тестом не доказывается.

## Найденные и исправленные ошибки

1. После снятия защиты stopService() мог оставить TUN: Android продолжал держать
   привязку к VpnService. AutomationService теперь отправляет владельцу ACTION_STOP
   для явного закрытия мастер-дескриптора. После пересоздания AutomationService
   выполняется очистка существующей собственной службы без создания лишней службы
   в обычном режиме. Проверка снятия защиты теперь ждёт удаления VPN-сети Android,
   а не только сохранённого статуса OFF.
2. При завершении AWG возникало реальное падение :protected с IllegalArgumentException
   «Service not registered». Android очищал привязку Service-контекста раньше
   отложенного releaseOwned(). ProtectedAwgClient теперь привязывается через
   Application-контекст, сбрасывает bound до unbind и допускает повторную очистку.
   Владелец отсоединяет ссылку на клиент до освобождения привязки.

После исправления оба AWG-профиля прошли по два цикла ON → удерживаемое OFF →
снятие галочки → прямой доступ без новых падений. Повторные браузерные проверки
обоих AWG и qWDTT также прошли. В tearDown opt-in тестов добавлена проверка
ApplicationExitInfo на новые CRASH/CRASH_NATIVE/ANR в защищённых процессах.

Один сравнительный запуск был ошибочно прерван перекрывающимся запуском теста;
его результат исключён. Он повторён последовательно. Исходные настройки после
этого восстановлены и проверены по исходной контрольной сумме. Инструментальные
тесты больше не запускаются одновременно на одном телефоне.

## Дополнительные функциональные проверки

- Защищённый режим: AUTO дома освобождает VPN; ручное ON действует дома;
  возврат ON → AUTO дома отключает VPN; возврат OFF → AUTO вне дома подключает VPN.
- Защищённый режим: ручное OFF блокирует DNS и внешний TLS; реальная плитка
  включает/останавливает VPN; шесть быстрых нажатий сохраняют последнюю команду;
  снятие галочки после OFF возвращает прямые DNS/HTTPS без оставшегося VPN-маршрута.
- Реальные переходы роутер без защиты → Keen_5G → обратно: удерживаемый VPN
  сохранялся на всех этапах. Независимое приложение за 45 секунд сделало 88 попыток,
  получив 0 внешних TLS-сеансов и 0 содержательных DNS-ответов.
- Финальный повтор на исправленной сборке: ONLY и EXCLUDE, ручное OFF, переход
  нерабочих AWG/Hysteria и отказ всех профилей прошли. По 88 попыток внешнего TLS
  и свежего DNS за 45 секунд — 0 успешных выходов в каждом режиме. Положительный
  контроль без VPN дал 11 успешных TLS-сеансов и 11 DNS-ответов. Проверка журнала
  завершений защищённых процессов также прошла без новых сбоев.
- Реальная домашняя автоматика: AUTO подключён вне дома; на Keen_5G снимает VPN;
  при возврате на исходный роутер автоматически подключает VPN. На всех трёх
  этапах проверены назначение VPN отдельному UID, DNS и HTTPS.
- Обычный режим: два цикла ALL / ONLY / EXCLUDE с независимым приложением и HTTPS.
- Обычный режим: два цикла возврата по таймеру, обработка BootReceiver и проверка,
  что старое событие таймера не отменяет новое ручное OFF с отключённым возвратом.
- Обычный режим: три реальных включения/выключения через плитку и 20 быстрых
  нажатий; последняя команда OFF сохраняется, самопроизвольного включения нет.
- ModelValidationTest: 26 тестов. Локальные проверки правил защиты/DNS: 97;
  qWDTT: 28 проверок конфигурации, 7 SOCKS-тестов и интеграционная цепочка TCP/UDP.
- assembleDebug, assembleDebugAndroidTest, lintDebug проходят.

Итоговая сверка всех сохранённых полей и данных профилей с исходной резервной
копией выполнена на телефоне: differing fields = []. Расшифрованные значения
и ключ шифрования на компьютер не выводились. Шифротекст файла может отличаться
после обычного сохранения из-за нового случайного IV AES/GCM; это не изменение
пользовательских настроек. Само восстановление зашифрованной копии до повторных
тестов также было подтверждено исходной контрольной суммой.

Журналы и снимки хранятся локально в artifacts/plain-router-*. Не все промежуточные
файлы обозначают успешные тесты: первоначальные FAIL/crash сохранены для диагностики.

Границы защиты остаются прежними: force-stop/гибель владельца TUN, отзыв разрешения
и запуск до установления VPN требуют системного механизма Android. Этот аудит
не заменяет внешний захват пакетов и испытание на сети с доступным IPv6.
