# Сборка AutoTurn

Требуются JDK 17 и Android SDK Platform 37 (пакет `platforms;android-37.0`). Исходники используют Gradle Wrapper; библиотеки туннелей уже включены в репозиторий.

## Получить исходники

```sh
git clone https://github.com/cveloy102/autoturn-vpn.git
cd autoturn-vpn
```

В Android Studio откройте корень проекта и выберите JDK 17 для Gradle. Укажите SDK через `ANDROID_HOME` либо через локальный `local.properties` с `sdk.dir`. Этот файл не коммитится. Установите Platform 37, Platform Tools и Build Tools. Локальные проверки проекта выполнялись с Build Tools 36.0.0; Gradle может запросить дополнительные SDK-компоненты.

## Собрать и проверить

```powershell
.\gradlew.bat :app:assembleDebug :app:lintDebug
```

На macOS/Linux:

```sh
sh ./gradlew :app:assembleDebug :app:lintDebug
```

APK создаётся в `app/build/outputs/apk/debug/app-debug.apk`. Библиотеки Xray и AmneziaWG включены в репозиторий; `libXray.aar` занимает около 95 МиБ.

Для обновления установленного приложения требуется прежний ключ подписи. Ключи, `local.properties`, SDK и кеши не хранятся в Git. Если доступен первоначальный ключ `.android/debug.keystore`, проект использует его для debug-сборки. На другом компьютере следует отдельно настроить SDK и подпись.

Без первоначального ключа Gradle создаст обычный локальный debug-ключ. Такая APK подходит для отдельной установки и разработки, но не для обновления официального APK. Удаление установленного приложения ради другой подписи удалит его профили; используйте отдельное тестовое устройство.

Lint-отчёт создаётся в `app/build/reports/lint-results-debug.html`. GitHub Actions выполняет сборку и lint без ключа официального выпуска; CI-артефакты предназначены для диагностики сборки.

## Устройство и инструментальные проверки

Проверки приложения находятся в `app/src/androidTest/`. Проверки реальных туннелей запускайте на специально выбранном устройстве: они могут переключать VPN. Документация серверных компонентов: [панель](../admin-panel/README.md), [relay](../admin-panel/relay/README.md).

Для текущего набора `androidTest` SDK должен быть доступен также в локальной `.sdk/`: зависимости используют `.sdk/platforms/android-37.0/optional/android.test.*.jar`. Этот путь не требуется для обычной сборки APK и lint. Затем на подготовленном тестовом устройстве:

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest
```

Перед запуском подготовьте профили, разрешения и тестовые APK по [TESTING.md](TESTING.md). Полный набор нельзя считать автономным тестом на пустом эмуляторе.

## Структура

| Путь | Назначение |
| --- | --- |
| `app/src/main/` | Интерфейс, импорт, хранение, автоматика, Xray и обновления |
| `app/src/debug/` | Управление для отладки, отсутствующее в release-варианте |
| `app/src/androidTest/` | Проверки моделей, UI, обновления и реальных подключений |
| `app/libs/` | Android-библиотека libXray и её происхождение |
| `third_party/amneziawg-tunnel/` | Исходники и нативные библиотеки AmneziaWG |
| `tools/prepare-update.py` | Подготовка APK и `update.json` для Releases |
| `docs/` | Инструкция, приватность и сведения о проверках |
| `admin-panel/`, `site/` | Отдельные серверные и веб-компоненты |

Готовую APK публикуйте как вложение GitHub Release, а не как файл исходников. Перед публикацией сверяйте versionName/versionCode, подпись, SHA256 и работоспособность на целевом устройстве.

## Выпуск обновления

1. Увеличьте `versionCode` и `versionName` в `app/build.gradle`. Сохраняйте прежний ключ подписи: другой ключ не обновит уже установленное приложение.
2. Соберите и проверьте APK. Затем выполните `python tools/prepare-update.py`: скрипт берёт версию из метаданных сборки, копирует APK в `releases/` и создаёт `update.json` с SHA256.
3. Создайте стабильный GitHub Release с тегом `v<versionName>` и прикрепите **оба файла**: `AutoTurn-<versionName>.apk` и `update.json`. Добавьте понятное описание изменений. Черновики и предварительные релизы не предлагаются пользователям.
4. Приложение читает `/repos/cveloy102/autoturn-vpn/releases/latest` без токена. Репозиторий должен оставаться публичным. Токены и ключи подписи никогда не включаются в APK или репозиторий.

Автоматическая проверка запускается при открытии приложения максимум раз в 24 часа, включая неудачные попытки; ручная кнопка всегда позволяет повторить проверку. Скачиванием занимается Android DownloadManager. После завершения APK копируется в приватное хранилище и проверяется перед выдачей установщику. При закрытии или гибели процесса системное скачивание продолжается; проверка завершится при следующем открытии. Установка без действий пользователя не выполняется.

## Перед выпуском

- Сборка и lint прошли; `versionName`, `versionCode` и тег согласованы.
- Прежняя подпись подтверждена, тестовые ключи и APK не попадают в Git или релиз.
- Проверены обновление поверх предыдущей APK и сохранение профилей.
- На тестовом телефоне проверены домашний Wi-Fi, мобильная сеть, ручные режимы, плитка и затронутый протокол с реальным трафиком.
- При изменении фонового поведения проверены закрытое приложение, выключенный экран и перезагрузка.
- У релиза есть APK, соответствующий `update.json`, описание изменений и честное указание непроверенных сценариев.
- Инструкция, история версий и подписи скриншотов соответствуют опубликованному поведению.

Исторические результаты не заменяют проверку новой версии. [Результаты тестов](TESTING.md) · [Сторонние компоненты](THIRD_PARTY.md) · [Участие в проекте](../CONTRIBUTING.md).
