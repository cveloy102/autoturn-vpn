## Критично

### 1. Android 10 и 11: автоматика падает, домашний Wi-Fi не распознаётся

В коммите `1f7a0fa` minSdk снижен с 31 до 29, но код слежения за Wi-Fi остался под Android 12.

- `AutomationService.java:111` вызывает конструктор `NetworkCallback(int flags)`. Он появился только
  в API 31 (проверено по `android-all` для Android 10: там есть только `NetworkCallback()`).
  На Android 10–11 это `NoSuchMethodError` в `onCreate()`: служба падает и перезапускается по кругу.
- Даже без падения имя сети берётся из `caps.getTransportInfo()` (строка 123). До API 31 `WifiInfo`
  не реализует `TransportInfo`, поэтому SSID всегда пустой: дом не узнаётся, VPN включён всегда.
- `ProtectedVpnService.homeSsid()` читает SSID через `WifiManager.getConnectionInfo()`. На Android 10–11
  две части приложения по-разному решат, дома ли пользователь, и могут дёргать VPN.
- Lint в CI это не поймал. На Android 12+ проблема не проявляется.

**Что делать:** на `SDK_INT < 31` создавать `new NetworkCallback()` и читать SSID через
`WifiManager.getConnectionInfo()`; проверить на эмуляторе Android 10. Либо вернуть `minSdk 31`.

## Высокий приоритет

### 2. Выпускаемые APK — отладочные

`AutoTurn-1.7.0.apk` со страницы релиза: `debuggable=true`, сертификат `CN=Android Debug`,
только подпись v2. Причина: релизы собираются `assembleDebug`.

- При включённой отладке по USB любой компьютер с ADB может выполнить `run-as app.autoturn.vpn`
  и подключить отладчик, то есть вытащить расшифрованные профили (ключи серверов).
- Нет сжатия кода, APK весит 120 МБ.
- Все обновления держатся на одном локальном `.android/debug.keystore` с паролем `android`.
  Потеря файла — обновить установленные приложения будет нельзя. Утечка — можно подписать поддельное обновление.

**Что делать:** добавить настоящий `release` buildType (`debuggable false`, `minifyEnabled true` с правилами
для libXray/AmneziaWG), подписанный **тем же ключом**, чтобы обновление ставилось поверх. Сделать резервную
копию ключа. Сменить ключ позже можно через ротацию (APK Signature Scheme v3), без переустановки.

### 3. «Дом» определяется только по имени Wi-Fi

Точка доступа с тем же SSID выключает VPN, а в защищённом режиме снимает блокировку
(`ProtectionRules.needsBarrier(..., atHome)`).

**Что делать:** при добавлении домашней сети запоминать ещё BSSID и считать домом только совпадение обоих.

### 4. Реальный IP сервера в репозитории

Реальный IP VPS есть в `app/src/androidTest/.../QwdttAuditTest.java:145` и `docs/PROTECTED-MODE.md:137`.
Встроенное обновление читает GitHub без авторизации, значит репозиторий публичный. Удалённая папка
`admin-panel` остаётся в истории git. Паролей и ключей серверов в истории не найдено.

**Что делать:** брать IP в тесте из локального параметра, убрать из документации; при необходимости
сменить IP или почистить историю.

## Средний приоритет

### 5. Расход батареи
`PARTIAL_WAKE_LOCK` без таймаута всё время работы VPN (`XrayVpnService.acquireWakeLock`,
`ProtectedVpnService.acquireWakeLock`). Проверки каждые 5–60 с (2–4 HTTPS-запроса в отдельных потоках).
`StatusStore.set` отправляет broadcast даже без изменения статуса, а `MainActivity` на каждый broadcast
заново расшифровывает настройки в UI-потоке.
**Что делать:** wake lock только для qWDTT; не слать broadcast при неизменном статусе; замерить расход.

### 6. Автовозврат в «Авто» на Android 12+
В манифесте нет `SCHEDULE_EXACT_ALARM`, поэтому на Android 14+ ставится неточный будильник, а из него
`startForegroundService` может выбросить `ForegroundServiceStartNotAllowedException`, которое молча
глотается. Подстраховка — таймер в работающей службе и событие включения экрана. Вывод по коду,
на устройстве не проверялось.
**Что делать:** ловить это исключение и показывать статус/уведомление.

### 7. DNS для адреса сервера
`EndpointResolver.boundedLookup` использует `Network.getAllByName` (системный DNS), хотя комментарий
в `ProtectedVpnService.startEngine` говорит, что адреса разрешаются по HTTPS. Подмена ответа не даёт
перехватить трафик (ключи/сертификаты проверяются), но может помешать подключению.
**Что делать:** использовать `BootstrapDns` (DoH) или исправить комментарий.

### 8. Версия не поднята
В ветке `versionCode 31`, `versionName 1.7.0`; `AppUpdater` предлагает только больший код.
**Что делать:** перед релизом поднять версию и слить ветку в `main`.

### 9. Покрытие тестами
27 юнит-тестов есть только в этой ветке (в `main` нет) и проверяют мелкие функции. Логика решений
`AutomationService.applyDecision/finishHealth/recover` и слияние в `SecureStore.save/mergeProfiles`
юнит-тестами не покрыты. 18 файлов `androidTest` в CI не запускаются.
**Что делать:** вынести логику решений в чистый класс с тестами; добавить в CI эмулятор (API 29 и свежий).

## Низкий приоритет

10. `Hysteria2Config`: `insecure=1` → `allowInsecure`. Предупреждать при импорте или требовать `pinSHA256`.
11. После импорта из буфера ссылка с ключами остаётся в буфере. Очищать после успешного импорта.
12. `DebugControlReceiver` (debug source set) есть в релизном APK. Защищён `android.permission.DUMP`,
    вызвать можно только через ADB. Уйдёт после п. 2.
13. `creds.go` содержит ID/секреты официальных приложений VK. Не секреты владельца, но VK может их
    сменить, и qWDTT перестанет работать.
14. `addJavascriptInterface` в `QwdttCaptchaActivity` виден всем фреймам страницы VK. Худший случай —
    неверный токен и повтор капчи.
15. `MainActivity` 1 490 строк, `AutomationService` 711; `EndpointResolver`/`EndpointCache` написаны
    в одну строку без пробелов. Сложно поддерживать.

## Что сделано хорошо

- Настройки зашифрованы AES-GCM с ключом в Android Keystore; `allowBackup=false`, cleartext выключен.
- Встроенное обновление проверяет хост, размер, SHA-256, версию и подпись APK.
- Компоненты не экспортированы, плитка не выключает VPN на заблокированном экране.
- Секреты не пишутся в логи; экспорт предупреждает об открытом тексте.
- Защищённый режим при неясной ситуации блокирует трафик (fail-closed).
- Импорт строго валидирует ссылки и ограничивает размер файлов.
